# Cheat sheet · Capítulo 12 — Migraciones de base de datos con Flyway

*Java Esencial · Volumen 2: Spring Boot · código del capítulo: tag `v2-cap12`*

## En una frase

Sabes dejar el esquema de la base de datos en manos de Flyway: scripts SQL versionados e inmutables en `db/migration`, Hibernate solo validando con `ddl-auto=validate`, y los mismos scripts para H2 en desarrollo y PostgreSQL en producción.

## Lo esencial

| Elemento | Para qué sirve |
|---|---|
| Migración | Script SQL versionado que describe un cambio incremental del esquema |
| `ddl-auto=create-drop` / `update` | No valen en producción: el primero borra los datos en cada reinicio; el segundo solo añade, nunca modifica ni elimina, y no deja historial |
| `flyway-core` | Dependencia de Flyway; sin `<version>`, la gestiona Spring Boot. Al añadirla, Flyway se autoconfigura |
| `V{versión}__{descripción}.sql` | Nombre obligatorio: `V` mayúscula, versión (`1`, `1.1`, `2`), dos guiones bajos y descripción con `_` |
| `src/main/resources/db/migration/` | Ruta por defecto donde Flyway busca los scripts (`classpath:db/migration`) |
| `flyway_schema_history` | Tabla que crea Flyway con cada migración aplicada: `version`, `description`, `checksum`, `success` |
| checksum | Huella del contenido del script; si cambia después de aplicarlo, Flyway detiene el arranque |
| Inmutabilidad | Un script aplicado no se toca; cada cambio nuevo va en `V3`, `V4`... |
| `spring.jpa.hibernate.ddl-auto=validate` | Hibernate comprueba que las entidades coinciden con el esquema, pero no crea ni modifica tablas |
| `spring.flyway.enabled=true` | Activa Flyway en el perfil (`application-dev.properties` y `application-prod.properties`) |
| `spring.sql.init.mode=always` | Mantiene `data.sql` en desarrollo: Flyway crea las tablas y después Spring inserta los datos |
| `spring.flyway.locations` | Cambia o amplía las rutas de scripts, por ejemplo para separar los específicos de cada motor |
| SQL estándar (`GENERATED BY DEFAULT AS IDENTITY`) | El mismo script sirve en H2 y en PostgreSQL sin tocar una línea |
| Columna `NOT NULL` en tabla con datos | Tres pasos: añadirla nullable, rellenar las filas con `UPDATE` y poner después la restricción |

## Código mínimo

La dependencia en `pom.xml`:

```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
```

Lo que cambia en `application-dev.properties` (en `application-prod.properties`, las dos primeras líneas):

```properties
spring.flyway.enabled=true
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
spring.sql.init.mode=always
```

Una migración incremental, `V2__aniadir_isbn_a_libro.sql`, y el campo que la acompaña en `Libro.java`:

```sql
ALTER TABLE libro ADD COLUMN isbn VARCHAR(20);
```

```java
@Schema(description = "ISBN (opcional, vuelve al catálogo en el Capítulo 12)", example = "978-84-376-0494-7")
private String isbn;
```

## Comandos y peticiones

```sql
-- En la consola H2: qué migraciones se han aplicado
SELECT * FROM flyway_schema_history;
```

## Errores típicos

- **`FlywayValidateException: Migration checksum mismatch for migration version 1`** → alguien ha editado un script ya aplicado. Revierte el cambio y crea un script nuevo (`V3__renombrar_columna.sql`) con la corrección; no desactives la validación.
- **Los datos desaparecen en cada reinicio con Flyway activo** → sigue puesto `ddl-auto=create-drop`, que borra las tablas al parar, incluida `flyway_schema_history`. Con Flyway usa `validate` o `none`.
- **`NULL not allowed for column "EDITORIAL"` al aplicar una migración** → has añadido una columna `NOT NULL` a una tabla con filas. Añádela nullable, rellena con `UPDATE` y aplica después `ALTER COLUMN ... SET NOT NULL`.
- **`Successfully validated 0 migrations` y el esquema vacío** → Flyway no encuentra los scripts. La ruta es exactamente `src/main/resources/db/migration/` (no `migrations`, no `src/test`) y el nombre empieza por `V` mayúscula, número y doble guion bajo.
- **`Schema-validation: missing column [isbn] in table [libro]`** → has añadido el campo a la entidad sin su migración. Crea el script SQL antes que el campo, o a la vez.

## En el Proyecto Biblioteca

Entra `flyway-core` en el `pom.xml` y nacen `V1__crear_esquema.sql` (tablas `libro`, `usuario` y `prestamo`, más dos índices) y `V2__aniadir_isbn_a_libro.sql`. `Libro.java` recupera el campo `isbn`, y los dos perfiles pasan a `spring.flyway.enabled=true` con `ddl-auto=validate`. Orden de arranque: Flyway aplica las migraciones pendientes, Hibernate valida el esquema y Spring ejecuta `data.sql`.
